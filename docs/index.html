    Shading: how likely a team holding the ball in each cell is to score before losing it (xT, a model fitted on StatsBomb Open Data from men’s international tournaments). It ignores defenders.     Pass network

    This half · every 5 minutes
    Who passed to whom in the current half, from the event log. The receiver is not recorded, so it is taken to be the next player of the same team on the ball. Circle size: passes made plus received; line width: passes between the two; colour: groups that pass mostly among themselves (modularity split); outlined ring: the most central player (highest betweenness, the share of shortest passing routes between team-mates that run through them). Each team is drawn attacking left to right.

      About this replay

      • Synthetic data. Clubs, players and events come from a seeded simulator. No real match data.
      • Replay, not live. The page replays a pre-built bundle. No server and no network calls.
      • Ask PitchSide's suggested answers were built at build time by a third agent, the Analyst, and checked by code: every number, name, time window and cited event. An answer that fails is replaced by a refusal. The page never calls a model; typed questions go only to a server you run on your own machine (scripts/ask_server.py), and only after you click Live (local).
      • Drafts come from an agent on Microsoft Foundry, run at build time. A deterministic verifier checks every claim before it can air. The replay never calls a model. Six drafts with planted errors come from a rule-based drafter, as test cases for the verifier.
      • Spanish comes from templates and a glossary and has not been reviewed by a native speaker.
      • Win probability is a simple Poisson model with stated assumptions, not a prediction about real football.
